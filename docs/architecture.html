TruckTracker-Analyst

配送の実績（TruckTracker）と販売管理の粗利を組み合わせて、得意先ごとに配送してどれだけ利益が残るかを自動で計算します。
Excel（秋田配送-得意先別）での手作業の集計をアプリにしたものです。

2. 全体の流れ

分析アプリ（緑）は、ほかの2つのシステムのデータを読むだけです（書き換えません）。

記録・変更する 読むだけ（データを変更しない） 配送管理 収益分析アプリ 販売管理 外部サービス リクエスト レスポンス

3. 配送経費の割り振り方

期間経費 ＝ 支店の月間経費 × 月数（月の途中は日割り）

この期間経費を得意先に割り振ります。

  • 方法A　回数で割り振る（Excel と同じ）: どの得意先も1回の単価は同じ（例: 6〜8月 約6,100円/回）
  • 方法B　距離も考えて割り振る（初期設定）: 「回数で分ける分」と「距離で分ける分」に分けて割り振る

例（期間経費 100,000円・距離分 50%・各社1か所ずつ配送）

複数か所を回る配送の場合

走行距離を、支店からの距離の帯ごとに、その帯まで行く得意先で分け合います。遠い得意先ほど多く負担し、合計は実際の走行距離と同じです。

注意点
  • 距離は地図上の直線（走行距離 = 支店 → 到着順 → 支店）。実際の道のりとは違います。
  • 位置が未登録の配達先は、同じ配達先の他の配送か、全体の平均で補います。
  • 距離分の割合は、燃料費が経費に占める割合などを目安に決めてください。

4. 散布図でわかること

得意先を点で表示します。横 = 回数、縦 = 支店からの距離、点の大きさ = 営業利益の大きさ（赤字は損失の大きさ）。

赤（塗りつぶし）回数で割っても距離で割っても赤字 → 優先して見直し

技術情報（システム担当者向け）

TruckTracker（配送管理）

  • 場所: repos\TruckTracker
  • HTML / Vanilla JS、Bootstrap 5.3、Supabase JS v2、Leaflet。public/ を Netlify で公開
  • DB定義: supabase/schema.sql（RLS = allow_all のため anon key で書込可能）
  • 集計の参考実装: admin.js の aggregateDestData / periodMonths

TruckTracker-Analyst（収益分析アプリ）

  • 場所: repos\TruckTracker-Analyst
  • C# / .NET 10 / WPF、MahApps.Metro、CommunityToolkit.Mvvm、Dapper、xUnit
  • SQL Server は SELECT のみ（ReadOnlySqlGuard）、Supabase は HTTP GET のみ
  • 計算: Domain/ProfitCalculator.cs、距離: Domain/Geo.cs（Haversine の Km、コース走行距離の按分 RouteShares）、到着順の並べ替え: Infrastructure/SupabaseDeliveryRepository.cs、散布図: Presentation/ScatterChart.cs
  • 配布: dotnet publish の publish/（.NET 10 Desktop Runtime が必要）
