# 配送計画の自動作成（検討中・2026-11-14 相談）

目的: 販売管理の当日売上伝票と配送管理のコース・実績を突き合わせ、効率のよい配送計画案を自動で作る。
現状は人が伝票を見て配送管理に手入力している。

凡例: [ ] 未着手 / [x] 完了

## 前提・制約
- 両DBとも**読み取り専用**（絶対ルール）→ アプリは「計画案の表示・出力」まで。配送管理への登録は人が行う（自動登録するならルールの見直しが必要）。
- 顧客情報を外部に送らない → 住所から座標を出す外部の住所検索サービスは使わない。移動時間は過去の `stop_records.arrived_at` の実績から出す。

## 使えるデータ
- 当日の配送先: 売上伝票の得意先コード → `destinations.sales_customer_code`
- 積載量: `trucks.max_load`、`packaging_unit_weights`
- 既存のコースと順番: `courses`(day_of_week) / `course_stops.stop_order`
- 配達先間の移動時間: 過去の `stop_records`（同じ日報内で連続する到着時刻の差）

## 足りないデータ
- 緯度経度・距離（`destinations.address` は文字列のみ）
- 伝票ごとの重量（商品マスタに重量があるか未確認）
- 時間指定（午前必着など）: どちらのDBにもない

## ユーザーに確認すること
- [ ] 「効率」の基準: 走行距離 / トラック台数 / 作業時間のどれを一番減らしたいか
- [ ] 1日の配達先件数・トラック台数
- [ ] コースは曜日ごとに固定で組み替えたいのか、毎日ゼロから組み直したいのか
- [ ] 計画案の出し方（画面表示 / CSV / 印刷）

## 段階案
### Step 1: 当日配送先リストの自動作成（最適化なし・効果が最も大きい見込み）
- [ ] 販売管理: 指定日の売上伝票 → 得意先一覧を取得（伝票日付＝配送日でよいか確認）
- [ ] 得意先コード → 配達先の対応付け（コード未設定・対応なしは警告表示）
- [ ] 曜日に合うコースへ割り当てた案を表示（どのコースにもない配達先は「未割当」として表示）
- [ ] 概算重量（計算できる場合）と `max_load` の比較

### Step 2: 回る順番の最適化（外部API不要）
- [ ] 過去実績から配達先間の移動時間表を作る（実績のない組み合わせの扱いを決める）
- [ ] コース内の順番を組み替えた案を出す（件数が少なければ全通り、多ければ近い順にたどる簡易な方法）

### Step 3: トラックへの振り分けまで含めた最適化（データが揃ってから）
- [ ] Google OR-Tools（NuGet、PC内で動く）で積載量を守って車両に振り分け
- [ ] 前提: 距離・移動時間データと伝票ごとの重量が揃っていること
